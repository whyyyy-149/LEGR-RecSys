# Stage 2：SID 生成式检索（TIGER-lite）

```
文本 → Qwen3-Embedding(1024d) → RQ-VAE(4 级) → SID(c1,c2,c3,c4)
                                              ↓
用户历史 SID 序列 (10 物品 × 4 = 40 token)
                                              ↓
                      4 层 causal Transformer (0.6M 参数)
                                              ↓
                    trie 约束的 beam search(50) → 候选物品
```

## 1. 跑法

```bash
# 1) 造 SID（约 2.5 分钟）
python scripts/v2/sid/build_rqvae.py --epochs 120

# 2) 历史 → SID 序列（约 10 秒）
python scripts/v2/sid/build_sid_seq.py

# 3) 训练生成器（CPU 约 17 分钟 / 8 epoch）
python scripts/v2/sid/train_generator.py --epochs 8

# 4) 约束解码 + 评估（全量 5,744 用户，约 7 分钟）
python scripts/v2/sid/decode.py --beam 50
```

产物都在 `scripts/v2/sid/outputs/`：`rqvae.pt`、`sid_codes.npy`、`sid_seq.pkl`、
`generator.pt`、`decode_report.json`。

## 2. Stage 1：SID 质量（RQ-VAE）

| 指标 | 结果 | 门槛 | 说明 |
|---|---|---|---|
| 码本使用率 | 100 / 95.7 / 87.5 / 86.3% | ≥90% | 没有坍缩 |
| 每级困惑度 | 162 / 210 / 211 / 216 | 接近 256 | 分布均匀 |
| SID 冲突率 | **3.31%** | <5% | 813 个物品重名，需消歧 |
| 重构余弦（中心化） | 0.725 | 0.7+ | 32 维 latent 的上限 |
| 前缀邻域 L1 | **74.2%** | >40% | 第一级码字 = 粗类目 |

关键取舍：**latent 越大重构越好，但量化越粗、冲突率越高**。
latent 64 → 冲突 15%；latent 32 + 4 级 → 冲突 3.3%。

## 3. Stage 2：生成式检索（全量测试集 n=5,744）

| 方法 | Recall@50 | HR@10 | 备注 |
|---|---|---|---|
| 随机 | 0.20% | 0.04% | 50/24,587 |
| **热度基线**（Top-50 热门，排除历史） | **7.45%** | 2.86% | 所有人推同样的 50 个 |
| 纯语义 FAISS（last-item query） | 4.32% | — | 第一版召回 |
| 纯协同 SASRec（全量排序） | 8.48% | 3.14% | ID 基线 |
| **生成式 SID（beam=50）** | **8.86%** [8.17, 9.59] | **3.95%** [3.46, 4.46] | 0.6M 参数 / 8 epoch |

Teacher-forcing 下：exact match 0.57%，逐级准确率 0.09 / 0.19 / 0.37 / 0.44
（越靠后的码字熵越低，越好预测）。

## 4. 三个必须知道的发现

### ① 不加约束，生成的基本是"不存在的物品"

早期未训练模型：**无效生成率 100%**；训练 8 epoch 后降到 4%。
trie 约束把无效生成率**恒定为 0**，代价是每步只能走真实前缀。
这是生成式检索能不能上线的那道坎。

### ② 热度基线 7.45%，是所有模型的及格线

Amazon 5-core 的交互极度集中在头部：Top-50 热门物品覆盖了 7.9% 的交互。
**给所有人推这 50 个，Recall@50 就有 7.45%**——比 SASRec 只低 1 个点。

所以任何召回模型的真实贡献是「超过热度多少」：

| 方法 | 相对热度基线 |
|---|---|
| 纯语义 FAISS | **−3.1pp（低于热度）** |
| SASRec | +1.0pp |
| 生成式 SID | +1.4pp |

### ③ 这解释了为什么两阶段系统端到端打不过 SASRec

语义召回 4.32% 连热度基线都没过，后面重排再好也只能在这个天花板下工作
（端到端 ≈ 4.28% × 0.61 ≈ 2.6% < SASRec 3.14%）。
**瓶颈从头到尾都在召回覆盖，不在排序。**

## 5. 局限（写清楚，面试才可信）

1. 单 seed、8 epoch、0.6M 参数；没调过参，不是 SOTA。
2. SID 3.3% 冲突未消歧（TIGER 用追加 token 解决），这部分物品在生成端不可区分。
3. beam=50 时平均候选 55.2 个（含同码组展开），与"严格 50"略有差异。
4. SID 只用文本构建，缺协同信号——冷启动物品有优势，热门物品区分度弱。
5. 负对照（打乱 target）显示 Recall@50 = 4.6%，与热度基线 7.45% 同量级，
   说明生成器相当程度上在推"热门 SID"；真实增益约 +1.4pp。

## 6. 下一步（如果继续）

- SID 加协同信号（文本 + SASRec embedding 拼接），提升热门物品区分度
- 4 级 → 3 级 + 冲突消歧 token，缩短解码步数
- 序列级 beam 重排（用 beam score + 热度做线性融合）
- 和 LEGR 重排器串联：生成式召回 Top-50 → listwise 重排
